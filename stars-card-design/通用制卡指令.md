## 开始工作

1. 读取 输入规范（见本文件对应章节），使用 `assets/intake.template.json` 整理照片、事实来源、卡型、风格、背面和交付方式。先复用已提供资料；只询问会阻断人物识别、配对或制作的缺失项。
2. 有照片先看图。没有可用人物照片时，可完成版式、通用背面和待填字段，但不能声称已完成保真人像卡。不要从旧聊天预览声称拿到了原图。
3. 对照 照片保真（见本文件对应章节） 确定原照片抠图排版或局部编辑路线；人物和文字不依赖整卡随机生成。
4. 根据卡型和风格读取 设计规则与提示词（见本文件对应章节）。先确定正面主体、收藏卡层级和共同背面，再扩展系列。只做用户要求的款数；用户未要求审批关卡时，先做可审阅成果并自行完成检查。
5. 需要印刷时读取 印刷与对位（见本文件对应章节），以印厂模板覆盖制作假设。需要 A4 拼版时读取 拼版工具（见本文件对应章节）。工具负责几何，不负责人物审核或 CMYK 印前认证。
6. 按 交付与质检（见本文件对应章节） 检查所有交付物；报告已完成、限制和待确认项，不能把数字效果图标为真实镭射工艺文件。

## 关键执行约束

- 单人卡只有一个主体；团队卡保留用户合照中的全部成员与原有关系，不将其他成员当作“背景人物”删除；多时期卡允许同一个人不同真实时期的照片作为明确主体面板。三者都不新增、复制背景人物。时期归属不明确时按用户的照片顺序暂排，省略年份。
- 默认中文沟通，姓名和队名保留用户给出的原文；不要自行翻译姓名或把不存在的资料填满。
- 用当前环境可用的图像编辑能力处理图像；如有专门的图像编辑技能/工具，按其规则调用。未获得更换人脸授权时，不重绘脸、身体、队服号码或 Logo。没有保真编辑能力就采用原图裁切/遮罩排版。
- 文本、Logo、边框、工艺蒙版尽量独立可编辑；小字在精确排版阶段叠加。用户提供 Logo 优先使用原始矢量/透明文件；缺失时用无品牌抽象纹理做待补背面，不能猜造真实球队标志。
- 同队/同系列通用背面默认克制、独立于正面风格，不暴露某个正面变体的材质、风格名或稀有度。用户明确要求个人资料背面或变体专属背面时才调整。
- 竖版成品默认 63.5 × 88.9 mm，横版交换宽高为 88.9 × 63.5 mm；含四周 3 mm 出血后分别为 69.5 × 94.9 mm、94.9 × 69.5 mm。重要信息默认距裁切边 5 mm。这是制作默认值，非所有印厂统一标准；横版设计不代表现有 A4 纵向 2×2 脚本自动兼容横卡。
- 同页粘贴版与双面版是两种交付，不能混用。粘贴版正反面并排、都正读，裁开后白背相贴；双面版按翻边方式重排背面位置，不镜像文字或 Logo。
- 默认 300 ppi 是有效像素检查目标；仅修改 DPI 标签或放大插值不能称作新增真实细节。
- 没有印厂 ICC、纸张及工艺要求时，交付带色彩说明的桌面打样版；不能声称完成生产级 CMYK / PDF/X 或已验证印刷机对位。

给出可点击的设计/文件入口，简述采用的卡型、风格、人物保真方式和印刷规格；明确哪些内容仍是空缺事实、待放置 Logo 或待印厂确认。完整清单写在交付说明中，不在聊天里重复所有技术细节。

# 按运行能力适配

## 先识别能力，再承诺产物

使用宿主实际提供的能力，不从品牌名推断能力。网页聊天、终端代理、API 接入、可视化节点工作流中的同名模型，能力可能不同。无需每次打印一份能力清单给用户；只说明影响任务交付的限制。

| 实际能力 | 可完成的工作 | 不能冒称完成 |

| 只有文本 | 输入梳理、版式、尺寸、提示词、印刷说明、质检计划 | 已看照片、已生成卡图或下载文件 |
| 能看图，不能编辑 | 观察构图和可见元素，制作针对照片的设计说明与编辑提示词 | 人物已抠出、图像已合成 |
| 能文生图，不能参考图编辑 | 原创无人物背景/卡框、材质概念 | 新生成的人脸就是用户原照本人 |

| 能运行 Python 和写文件 | 在 Pillow、ReportLab 等依赖实际可用时运行拼版；无图像生成能力也可处理已提供的图稿 | 脚本执行就证明实机对位、CMYK 或人脸正确 |

## 能力不足时的可执行产物

- 缺图像编辑：提供准确引用用户上传图的编辑提示词，写清保留人物、只改哪些区域、卡型、方向和文字；若有精确排版能力，仍可用原照片嵌入版式。
- 不能看图：不要猜合照人数、球队、奖杯内容或照片构图。用用户文字资料做方案；把“请保留原图中所有成员”作为编辑约束，不说已确认人数。
- 缺文件运行环境：可交付提示词、布局坐标、人工导出和打印步骤，标明未生成 PDF。用户需要实际文件时，给出本包脚本的运行方法或让有相应能力的工具继续；不能编造附件。
- 只支持单条提示词的工具：给独立完整的视觉提示词；照片、精确文字和 Logo 在后续排版环节处理。若工具不支持保真编辑，只生成装饰素材。
- 缺图片或私有文件不可读：先完成不依赖它的部分；从当前聊天重新取得素材，不能依赖另一个平台的本地路径。

## 工具调用原则

查看图片使用宿主的图片查看能力；生成或编辑使用实际可用的图像工具；处理 PDF 使用文件/排版工具或已测试脚本。这些是能力名称，不要求某个具体函数。宿主有对应技能时遵守其规则；没有时不把它当作必装前提，也不自动切到收费 API。

不把某平台的 `image_gen`、`view_image`、`run_shell_command`、`$技能名` 或 `/技能名` 写成全局必需接口。原生技能宿主按自身方式加载；纯聊天以用户粘贴/上传的指令执行。技能不能给原本没有图像编辑或代码执行能力的模型增加这些能力。

## 素材在平台间的交接

交接包只携带必要的源照片、已确认事实、Logo、当前版式和导出规格；人像不默认放进可公开分发的技能包。路径是当前环境的引用，不是通用下载链接。附件 ID、图像引用、文件 URL、遮罩黑白语义都按目标工具定义确认。

保留用户已认可版本，注明当前产物为原图排版、AI 参考编辑、概念背景或生产稿。不得把参考编辑当成未重绘的源照片；有明显脸部变化时回退源照片排版或明确未通过保真检查。

# 输入规范

先把现有输入整理成 `assets/intake.template.json` 的结构。该模板是人工/代理的需求表，不是拼版工具的参数；拼版工具使用另一个 `print-job.template.json`。

## 最小可执行输入

| 项目 | 要求 | 缺失处理 |
|---|---|---|
| 人物照片 | 可读取原始文件，注明每张照片里哪位是主体 | 缺照片只做版式；多人照主体不明需问清，不能猜 |
| 人物标识 | 用户给出的姓名或任务内部 ID | 姓名可省略，内部 ID 不当作真实姓名上卡 |
| 卡型 | `single`、`team` 或 `growth` | 默认 single；合照且用户要求团队卡时用 team，多张照片不自动认定为成长卡 |
| 方向 | `portrait` 或 `landscape` | 用户指定优先；团队横卡保留全部成员，不按单人卡裁切 |
| 风格 | `retro`、`magazine`、`holographic` 或明确自定义 | 最近明确选择优先；无选择用克制现代收藏卡，并标为假设 |
| 交付 | `design`、`paste`、`duplex`、`singles`，可多选 | 未要求印刷时先做设计，不替用户增加复杂工艺 |

## 事实与来源

`facts` 的每个字段使用 `{value, source}`，未知值是 `null`，不使用看似真实的示例资料。`source` 写用户消息、附件文件名和位置，或经用户要求查询的可靠来源与日期。

- 字段可包含 name、team、jersey_number、position、season、birth_date、height、weight、statistics、awards；均为可选。
- 数据必须带对应赛季/时间范围、单位及来源。不把身高体重从外貌估计出来。
- 网图文件名、球衣印花或照片 EXIF 不足以确认身份、号码所属赛季、时期或荣誉。
- 用户自述可以作为用户提供资料使用，但不称作已独立验证。
- 自定义卡号写入 `design.catalog_id`，区别于球衣号。不要默认增加 Rookie、MVP、签名、1/1、限量、官方认证等声称；用户要求装饰性卡号也需标明自定义系列。
- 无资料时删掉对应模块，留下空间，不用随机统计填版。

## 照片记录

每项 `photos[]` 使用：

```json
{
  "id": "photo-01",
  "path": "./photos/source-01.jpg",
  "subject": null,
  "stage_label": null,
  "captured_at": null,
  "source": "用户上传原图",
  "approved_identity_reference": false,
  "allowed_edits": ["crop", "mask", "exposure", "white_balance"]
}
```

`subject` 是用户指认的对象，例如“左侧穿白色球衣的人”，不是模型识别出的姓名。`approved_identity_reference=true` 仅用于用户确实认可过且文件可读取的版本。`captured_at` 和时期标签未确认时保持 null。

成长卡通常用 2–4 张照片作为设计建议，不是硬性数量限制；照片不足不能通过年龄生成补齐历史。可用单图卡替代，并说明缺少的真实时期素材。

## 背面与印刷输入

- Logo：原始 SVG/PDF/透明 PNG，记录用户指认的球队及文件来源；禁止 AI 重绘真实 Logo。照片中的 Logo 过小不能直接当作可印刷原稿。
- `back.mode` 默认 `team_common`：同一球队/系列共用背面。正面可变，背面不加某个球员的资料。队伍未确认或 Logo 缺失时只交付明确的待补稿。
- `production.trim_mm` 默认 `[63.5, 88.9]`；`bleed_mm=3`；`safe_mm=5`；`target_ppi=300`。印厂明确参数优先。
- 横版用 `design.orientation="landscape"` 且 `production.trim_mm=[88.9,63.5]`。方向与尺寸冲突时先解决，不旋转图或拉伸图假装兼容。团队卡不加未确认队名、赛事、年份或荣誉；合照里现有成员都是主体。
- `production.duplex_flip` 为 `long` 或 `short`，仅描述 A4 纵向驱动设置；手工翻纸需现场校准，不能从打印机品牌猜进纸方向。
- `production.finish` 区分 `digital_simulation`、`holographic_stock`、`holographic_laminate`、`foil` 等；真正工艺需供应商规范。

## 缺省行为

有足够素材就做，简要列出关键假设。事实缺失通过省略解决；人物不可访问、多人身份不明或正反配对不明会影响结果，必须先明确相关部分，其他独立部分可继续。不得把输入模板中的 null 直接印在成品上。

# 人物照片处理与保真

## 优先路线

1. 保存原文件并记录文件名/哈希，不覆盖。读取 EXIF 朝向后正常显示，确认主体是谁。
2. 首选原照片裁切、精细遮罩/抠图及非破坏性调色；背景、边框、光效单独制作。
3. 确需生成式编辑时，用原图作为编辑参考，只编辑授权区域，脸、头发、身体轮廓、队服及号码区域默认保护。编辑工具的遮罩语义先确认。
4. 把编辑后主体与原图对比，再叠入卡框。无法保持一致时回退原图，不用“更好看”作为换脸理由。

不要让整卡生成器同时猜人物、Logo、号码和小字。若只有生成整图的能力，明确其保真限制，并优先交付原图嵌入版式。

## 保留清单

- 脸型、五官比例、耳朵、发际线、痣/疤等可见身份特征。
- 肤色、年龄感、体型、手脚、姿态和器材形状。
- 队服花纹、球队文字、号码与位置，不把背号镜像。
- 原本被遮挡或出画的身体部位不凭空补成“历史事实”；尽量通过构图解决裁切。
- 毛发边缘、球拍/球棒/球等细部；不能出现明显白边、黑边或透明洞。

允许统一曝光、白平衡、轻度去噪和不同照片间的色调。默认不磨成塑料皮肤、不瘦脸、不增肌、不换表情、不跨时期统一年龄。修复低清的结果应标注重建细节风险；不能宣称恢复了原本不存在的真实细节。

## 多时期照片

- 只能使用同一人且用户已确认时期/顺序的素材；不通过人脸相似度自行认定身份。
- 每个时期保留当时真实外观，不把年轻照片改成现在的脸。
- 用面板、卡窗、相片切片或连续编号建立时间关系；这些照片是主体，不是背景装饰人群。
- 默认不印“成长轨迹”。年份未知就不印年份；用户确认的“初学/校队/现在”等词可以使用。

## 输出与检查

保留源照片、遮罩、主体透明 PNG 和最终合成稿；只有用户需要且工具实际支持时才承诺分层 PSD/其他工程文件。检查成品全图和 100% 人脸细节，特别核对眼睛、嘴、手指、衣服文字和背号。数字相似度最多辅助检查，不能代替视觉对照或人物身份确认。

有效分辨率按实际放置尺寸计算：`源裁切区域像素 / 放置英寸`。先做照片分辨率评估，再决定主体能放多大。低于目标时记录限制，改小图窗或索取高分辨率素材；插值不是新细节。

# 卡型、风格与生成提示

## 收藏卡结构

正面先确定可读层级：人物 → 姓名（如有）→ 球队/背号（如已确认）→ 自定义卡号/系列。用边框、内框、金属角、刻度、几何暗纹和徽章形容器建立收藏卡感；元素数量服务于层级，不必全部使用。

卡号是设计标识，不是球员事实。没有官方授权时不用官方发行商标、官方认证、真实签名仿造或误导性的限量编号。参考风格不等于复制某品牌卡框。

避免宣传图特征：大口号、整页介绍段落、大场景人群、背景复制人物和堆积光效。按 63.5 × 88.9 mm 实际大小检查，不按手机放大预览判断小字可读性。

## 单人卡

一个人物主图，优先半身或适合卡框的动作裁切。边框不能穿过眼睛、脸和关键信息。原照裁切不适合全身时保留半身，不生成不存在的腿脚。默认背景只用纹理、球场几何或无人物抽象空间。

## 多时期成长卡

真实时期照片构成 2–4 个面板，可一大两小、左右双窗或上下切片，避免把多个人物散在背景里。先保证每张脸在实际卡面大小上可辨认。照片太多时拆为一组时期卡，而不是挤满一张。

时间顺序与标签必须来自用户；不自动加入出生、夺冠、转会等故事。默认没有“成长轨迹”标题；可用已确认的系列名称或只保留姓名。多时期卡也能套用下列风格。

## 团队合照卡

根据用户选择支持横版 7:5；照片窗口优先容纳所有成员、奖杯和原有互动关系。可裁掉多余天空/建筑，但不能把边缘成员或前排成员裁没；原照已出画的肢体不生成补全。队名未确认时可用“团队珍藏卡”这样的卡型标题，不能从队服或横幅猜造正式队名、赛事和获奖等级。团体成员不是需要清除的“背景人物”。

优先将原照作为照片层嵌入，再制作边框与标题。参考图编辑需逐个检查成员是否遗漏、重复或变脸；未通过保真检查时不得称为原照直接排版。横版尺寸与现有 A4 脚本边界见印刷与拼版说明。

## 风格选择

| 风格 | 可用视觉语言 | 约束 |
|---|---|---|
| 复古 retro | 奶油纸色、细线框、双色网点、轻微纸纹、克制印刷错版感 | 老化只作用于装饰，脸和字保持清晰；不伪造年代或经典赛事 |
| 杂志 magazine | 强网格、紧凑姓名排版、细节照片窗、少量编辑式标注 | 保留卡框和卡号；不做长文封面，不塞虚构采访或统计 |
| 镭射 holographic | 银色基底、虹彩折射、棱镜细纹、箔感边框、局部高光 | 虹彩避开肤色及小字；屏幕效果不是实体镭射；真工艺另出分层 |
| 现代收藏卡（无选择时假设） | 简洁卡框、清楚姓名区、单个主色与局部金属感 | 不是既有确认偏好；不能替换用户明确的风格 |

风格变化时维持同一真实人物、姓名、队服和卡面信息。优先换边框、底纹、材质及排版，禁止无意改脸。

## 球队 Logo 通用背面

每个球队/系列建立一张共同背面：原始 Logo 是主角，辅以队色线条、运动几何和克制系列标识。不要带某个球员的姓名、背号、成长照片或统计，使它能适配本队整组卡片。

Logo 保持原比例、原图形和可辨识色彩；矢量优先。缺失时提供无品牌背面待补稿，不生成“像该队”的近似商标。不同球队分别关联背面；不能把一个队的 Logo 分配给所有卡片。

通常保持背面正读。可以采用对称装饰提升翻转容错，但文字和 Logo 不做镜像；不要用对称设计掩盖错误配对。

## 可复用提示词

以下是代理内部模板，先填入已经确认的信息；缺失项删掉。精确姓名/小字/Logo 应在后续排版叠加。

### 原图编辑 / 主体保护

### 杂志风卡框

“原创杂志编辑感收藏球星卡版式，竖版 5:7，紧凑网格、明确卡框、姓名区和小型卡号位。视觉重点留给真实球员照片，减少装饰，不包含采访文章、统计表或广告标语。背景无人，不生成任何具体姓名、号码、Logo。”

### 镭射卡框

“原创收藏球星卡的银色镭射视觉卡框，竖版 5:7，局部棱镜虹彩、细密箔纹、金属角饰，中心人物区域干净，肤色区与姓名区不铺虹彩。无人物背景、无复制人像、无文字、无 Logo，不包含‘成长轨迹’。这是数字视觉模拟，后续独立排版和工艺分层。”

这些 5:7 指成品视觉比例。生成背景后需按含出血比例适配 69.5:94.9，不能把整卡机械拉伸；应扩展无关键内容的边缘。

### 多时期卡拼版指导

“按输入中用户确认的顺序，将同一人各时期真实照片排成明确卡窗。每张保持自身时期外观，不重绘人脸，不添加背景人物，不编年份，不印‘成长轨迹’。保留统一收藏卡边框、姓名区和自定义卡号位置。”

这是排版说明；无法保真合成时逐张原图遮罩排版，不把提示词当作保真保证。

### 横版团队卡指导

“使用提供的团队合照制作一张横版 7:5 收藏球星卡。原照片是编辑目标，不是重绘人物的参考灵感。保留所有成员原有面孔、位置、服装、姿态以及原有奖杯和证书；不遗漏、不复制、不增补人物，不生成缺失肢体。照片窗口占主画面，适当减少多余天空；加入独立卡框、姓名牌式标题区和克制运动几何细节。未提供队名时使用‘团队珍藏卡’，不编赛事、年份、成绩、限量或官方认证。照片之外的装饰区域无人，不出现‘成长轨迹’。无法保真编辑时保留源照片像素，通过独立排版完成。”

# Sports-card style system

Use this reference when a task needs visual archetype selection, prompt construction, or a reusable template/rarity system.

## Archetypes

| Archetype | Visual language | Best use | Common failure |
|---|---|---|---|
| Annual base card | Clear sports photography, stable nameplate, team and year data | Large team or season sets | Generic layout with no story |
| Full-bleed stadium | Cinematic action photo, minimal corner typography | Emotional match moments | Text obscures the photograph |
| Competitive chrome | Sharp geometry, metallic depth, speed lines, luminous edge | Modern base and rookie cards | Too many flares and frames |
| Spectrum parallel | Stable layout with controlled color/material variants | Rarity ladders | Hue swaps with no rarity meaning |
| Archival retro | Warm stock, limited colors, halftone, old editorial type | Youth history and anniversary cards | Excessive distressing reduces clarity |
| Minimal premium | Large quiet field, one portrait, tiny labels, restrained metal accent | MVP, retirement, honor cards | Generic black-and-gold luxury styling |
| Color energy | Pale field with directed powder, ink, or spectral energy | Breakout and high-impact moments | Random splashes obscure silhouette |
| Hero comic | Original illustration, exaggerated action, motion marks | Youth and fan-focused special cards | Imitating a known insert or superhero |
| Local story | Athlete plus original city, food, landscape, and fan-culture symbols | Home-team and hometown editions | Background symbols overwhelm player |
| Geometric glass | Jewel colors, dark dividing lines, emblematic symmetry | Rare ceremonial inserts | Copying a recognizable stained-glass pattern |
| Auto/memorabilia | Signature or keepsake zone, serial field, certification hierarchy | User-supplied signature and memento cards | False authenticity or game-used claim |
| Acetate/booklet | Transparent layers, suspended subject, unfolding narrative | Digital motion or multi-moment stories | Novelty harms name and face legibility |

Commercial lines such as Topps Flagship/Chrome/Heritage/Stadium Club, Panini Prizm/Color Blast/Kaboom/Downtown, and Upper Deck Clear Cut are research references only. Never use their names as the output's style name or reconstruct their card face.

## Composition patterns

### Photo-led

- Subject occupies roughly 65–85% of card height.
- Place text in natural negative space or a controlled tonal fade.
- Use one visual climax and keep badges subordinate.
- Landscape works well for diving, swinging, dunking, celebrating, and multi-player moments.

### Competitive badge

- Choose one geometric family: cut corners, circular orbit, or track lines.
- Let the shared frame identify the series and the photograph identify the athlete.
- A rare version should change material, depth, or silhouette—not only color.

### Archival

- Use warm white rather than bright digital white.
- Limit the palette to two to four inks.
- Add fields with archival meaning: season, debut date, hometown, role, or achievement.
- Preserve facial clarity even when using grain, halftone, or registration offset.

### Illustrated story

- Write the card's story in one sentence before choosing imagery.
- Limit background symbols to three to five meaningful items.
- Preserve a readable silhouette at thumbnail scale.
- Keep an intentionally calm zone for the name and number.

### Honor edition

- Use an axis, emblem, or restrained symmetry for ceremony.
- Apply metallic accent to one hierarchy level only.
- Label digital keepsake windows accurately; do not imply physical memorabilia.

## Suggested product taxonomy

### Skeleton — choose one

- `photo`: full-bleed competition photography.
- `badge`: structured geometric frame.
- `archive`: retro editorial record.
- `illustration`: original narrative artwork.
- `honor`: ceremonial premium composition.

### Finish — choose zero or one

- `chrome`: metallic surface and controlled diffraction.
- `spectrum`: rainbow refraction or energetic color.
- `matte`: uncoated paper and soft ink.
- `acetate`: translucent stacked layers.
- `foil`: restrained metallic accent.
- `canvas`: tactile print grain.

### Story — choose zero or one

- `debut`
- `home_city`
- `champion`
- `clutch`
- `team_soul`
- `milestone`

## Rarity ladder

| Tier | Structural change | Finish change | Information change |
|---|---|---|---|
| Base | Standard frame | Paper or neutral gloss | Core identity |
| Special | Controlled break-out | Spectrum or canvas | Theme title |
| Limited | Distinct frame | Foil or acetate | Honest edition number |
| Unique | Bespoke composition | Combined finish | Unique commemorative copy |

Color must never be the only rarity indicator. Add a label, icon, material change, or layout change.

## Prompt vocabulary

Use generic visual language instead of commercial style names.

**Composition:** `full-bleed sports photography`, `centered hero portrait`, `low-angle action shot`, `asymmetric editorial layout`, `badge-based composition`, `quiet lower nameplate`, `large jersey number as background typography`.

**Finish:** `chromium metallic finish`, `subtle rainbow diffraction`, `matte vintage cardstock`, `embossed foil accents`, `transparent acetate layers`, `canvas paper grain`, `spot gloss`.

**Mood:** `stadium spotlight`, `directed color powder energy`, `archival season record`, `original local city iconography`, `championship ceremony`, `comic motion energy`, `museum-like restraint`.

**Negative constraints:** `no existing trading-card logos`, `no league trademarks`, `no copied card borders`, `no fake autograph`, `no unreadable microtext`, `no excessive lens flare`, `no cluttered background`.

# 印刷制作与双面对位

## 尺寸、出血和安全区

| 项目 | 本包默认值 |
|---|---|
| 方向 | 竖版 |
| 成品 / Trim | 63.5 × 88.9 mm，即 2.5 × 3.5 inch |
| 四边出血 | 各 3 mm |
| 含出血图稿 / Bleed | 69.5 × 94.9 mm |
| 重要内容安全区 | 默认从成品裁切边向内 5 mm，印厂要求优先 |
| 成品栅格，300 ppi | 750 × 1050 px |
| 含出血栅格，300 ppi | 约 821 × 1121 px，像素取整 |
| A4 | 210 × 297 mm；拼版默认纵向 |

63 × 88 mm 等也是可能的印厂规格，不能擅自与 63.5 × 88.9 mm 混用。尺寸按 mm 建版；像素是近似，不能因取整改变物理尺寸。300 ppi 栅格设计中 1 mm 约 11.81 px。

横版只交换宽高：成品 88.9 × 63.5 mm，含出血 94.9 × 69.5 mm；300 ppi 栅格约 1121 × 821 px。下文默认坐标、A4 2×2 图示及翻边矩阵针对竖卡，不能直接照搬到横卡。横卡可使用工具的 singles 模式；A4 横卡排版需按实际纸张方向重新计算位置与对位，不能旋转或缩小竖版拼版冒充标准横卡。

以含出血图左上角为原点：成品框是 `(3,3)` 到 `(66.5,91.9)` mm；5 mm 安全区是 `(8,8)` 到 `(61.5,86.9)` mm。背景延伸到含出血画布边，不能用白边补出血。出血内不能放姓名、Logo、背号或卡号。裁切后不能露出安全/裁切辅助框。

圆角是后加工轮廓，出血仍为完整矩形；关键元素避开圆角切除区。刀模半径由印厂确定，本包不擅自设为所有卡套通用标准。

## 裁切线与 PDF 页面框

- 单卡含出血图稿本身不带裁切线，方便印厂拼版。
- 另出带裁切线单卡 PDF，MediaBox 容纳图稿及外部标记；BleedBox 表示含出血区域，TrimBox 表示成品区域。
- 裁切线对齐成品边的延长线，线段画在含出血区域外，不能画在成品图上。本包工具使用距出血外边 1 mm 起、长 2 mm、线宽 0.2 pt 的黑色标记。
- A4 纸只有一个页面 TrimBox，不能用一个页面框冒充其中多张卡的裁切框；各卡以实际裁切线和坐标清单表示。
- 若印厂只要无标记文件，提供干净含出血稿，不强加裁切线和 A4 家用拼版。

## A4 同页粘贴版

目标是单面打印后裁开两块、白背相贴；不依赖打印机双面功能。

默认每页：

```text
A4 纵向，所有文字均正读
┌───────────────┐
│ 卡1正   卡1反 │
│               │
│ 卡2正   卡2反 │
└───────────────┘
```

每块含出血稿 69.5 × 94.9 mm，横纵间隔均 8 mm；整体宽 147 mm、高 197.8 mm，居中位置左上 `(31.5,49.6)` mm。两行对应两对卡。不同卡数向后续页延伸，不缩小尺寸塞更多卡。

正反面都不镜像、不倒置。先保留外侧配对标签，沿裁切线切出矩形成品，确认上下方向后白背相贴；压平固化，再按实际工具修整共同边缘/圆角。粘合剂、纸张厚度与干燥时间以材料说明为准，先打一对样卡，避免起泡、变形及过厚卡套不适配。

这不是“一张纸中线对折版”。若用户要折叠粘贴，需另设计折线、铰接关系、背面旋转和折叠容差，不能直接折本包的 8 mm 空隙版。普通贴合偏移不通过给某一面缩放补偿。

## A4 双面版

默认正面每页 2×2，共 4 张卡，页面内按行填充；背面依同一张纸逐卡配对。长边和短边规则都以 **A4 纵向、各页在 PDF 中正读、驱动设置匹配** 为前提。

正面页：

```text
1 2
3 4
```

长边翻转（驱动选长边）：背面页从左到右为

```text
2背 1背
4背 3背
```

短边翻转（驱动选短边）：背面页从左到右为

```text
3背 4背
1背 2背
```

两种背面页的内容均保持 PDF 页面正读；不再额外把卡图旋转 180°。匹配的打印驱动负责相应翻边方向。背面只改变位置，绝不把文字/Logo 水平或垂直镜像。若设备实际行为不同，先用校准页诊断驱动/进纸；不要同时改驱动和旋转稿，导致重复补偿。

缺卡位置保持空白，背面也映射到对应空位；通用背面虽然相同，也必须按几何配对。多页文档顺序是 `第1张纸正面 → 第1张纸背面 → 第2张纸正面 → 第2张纸背面`，不是先全部正面再全部背面。

## 坐标规则与偏移修正

采用左上角原点，单位 mm，卡片含出血矩形左上为 `(x,y)`，宽 `w`、高 `h`：

- 长边：`back_x = 210 - x - w`，`back_y = y`。
- 短边：`back_x = x`，`back_y = 297 - y - h`。

这组公式重排**卡的位置**，不镜像卡的像素。背面偏移参数 `dx,dy` 在背面 PDF 正读视角定义，正 x 向右、正 y 向下。

如果透光从正面观察背面相对正面偏移 `(ex,ey)`，所需修正：长边 `dx=+ex, dy=-ey`；短边 `dx=-ex, dy=+ey`。修正后再打一张验证。若不同角偏移不一致，考虑歪斜、走纸、纸张变形或缩放；整体平移无法消除这些误差。

## 打印校准

1. 使用 `scripts/impose_cards.py --mode calibration --flip long/short` 生成两页测试。四个位置带不同 A1/A2/B1/B2 标识、箭头及不对称角点，附 50 mm 标尺。
2. 打印 A4、实际大小/100%，关闭适合页面、无边距自动放大、页眉页脚和再次多合一。明确纸张类型、纸盒和纵向；只打印这张纸。
3. 驱动选择与文件相同的翻边方式。看正反配对、上下方向，量取 50 mm 标尺。无边距模式通常可能有放大，不能默认可用。
4. 透光检查各角中心位置，记录误差。手工双面进纸先在废纸标正反、进纸头，用测试页确定出纸与翻纸方式，再打印正式稿；不能通用承诺“翻过来直接放回”。
5. 本包建议以各角 ≤0.5 mm 作为个人打样目标，**不是设备保证或行业统一验收线**。用户/印厂可设容差。超出时调偏移、调整构图留白或换印刷方案；校准未完成就标“待校准”。
6. 若只能单面打印，改用同页粘贴版，不假称自动双面已验证。

## 色彩、纸张与镭射工艺

- 屏幕预览通常用 sRGB；专业印刷按印厂 ICC、纸张、设备和文件规范转换与软打样。不要无条件套一个通用 CMYK 配置，也不要仅改文件标签当作转换。
- 字体嵌入或转曲，小字尽量保留矢量。字号按实际尺寸读样，辅助小字通常从约 6–7 pt 检查，重要信息更大；这只是设计起点。
- 本包拼版工具生成 RGB 桌面打样 PDF，未嵌入印厂 OutputIntent，不声明 PDF/X，也不会自动生成 CMYK 分色。生产输出需另做印前检查。
- 数字虹彩是普通油墨中的色彩模拟；真正镭射依赖镭射卡纸/覆膜/箔等材料工艺。先确认供应商能否实现，再选择方案。
- 真实工艺如需白墨、箔、UV 等，按印厂要求独立生成 `WHITE` / `FOIL` / `UV` 等专色版；图层名和专色名仅为建议，最终以供应商命名为准。蒙版与彩稿必须同尺寸、同原点、同 TrimBox，不得在蒙版中重复印刷裁切线。黑色预览不代表已设置正确的专色、叠印或挖空。
- 肤色、文字和 Logo 下方是否铺白墨由材料和工艺确定；不能固定把人像全部透成银色。最小线宽、陷印、套准容差必须问印厂，禁止自行保证。

# 交付清单与质量检查

## 按实际任务交付

不是每次都制作所有格式；用户要求哪些模式就完成哪些，缺依赖时明确哪一项没有完成。

| 类别 | 内容 | 要求 |
|---|---|---|
| 预览 | 正面/背面并列，必要时系列总览 | 无裁切线，适合屏幕；不能作为印刷稿替代 |
| 设计母稿 | 实际可编辑工程文件、矢量排版或独立图层 | 人物、背景、Logo、文字、工艺分层；无法导出工程时明确格式限制 |
| 干净图稿 | 每卡正面含出血 PNG/TIFF/PDF、每队通用背面 | 物理规格明确，正反一致，无辅助线 |
| 成品视图 | 裁到 63.5 × 88.9 mm 的预览图 | 与含出血稿分开命名，避免误送印 |
| 单卡印刷 | 带裁切线且页面框正确的 PDF | 用户或印厂需要时提供 |
| 同页粘贴 | A4 PDF：每行同一卡正反配对 | 单面印，100%，不镜像，不误标折叠版 |
| 双面印刷 | A4 PDF：每张纸正反交替 | 标注 long/short、配对矩阵和校准状况 |
| 工艺文件 | 镭射材料说明、所需白墨/箔/UV 蒙版 | 仅实际制作并完成印厂规范检查时列为生产文件 |
| 交付说明 | 来源、尺寸、版本、色彩、打印设置、缺项、质检结论 | 真实写出限制，不用“全部通过”掩盖未测项 |

## 人物与资料检查

- [ ] 已看过原图和批准版本，对比了人脸、年龄感、体型、队服、号码及手部。
- [ ] 无额外背景人物、复制球员、残留抠图边或错误肢体。
- [ ] 多时期均为真实素材，顺序和标签有来源；无“成长轨迹”默认禁用文案。
- [ ] 姓名、队名、背号、赛季、数据均逐项有来源；未知字段已省略。
- [ ] 自定义卡号与球衣号分清；无虚构荣誉、签名或官方认证。

## 视觉与背面检查

- [ ] 实际尺寸可读，像收藏卡而非宣传海报；人物是第一视觉中心。
- [ ] Logo 与原文件一致，无拉伸、猜造或生成变体。
- [ ] 同队通用背面未混入单个球员字段；跨队背面正确映射。
- [ ] 镭射装饰未污染肤色、眼睛、队标或文字；模拟与实体工艺标注准确。
- [ ] 辅助框、占位文字、null、测试编号没有出现在正式卡面。

## 印前检查

- [ ] Trim 为用户确认尺寸；每边出血达到 3 mm 或供应商要求。
- [ ] 核心信息处于安全区，圆角附近无关键内容。
- [ ] 栅格素材有效 PPI 已检查；未以改 DPI/放大冒充高质量。
- [ ] 裁切线在出血外，无误裁到成品；单卡页面框正确。
- [ ] 字体已嵌入/转曲，中文不乱码、不缺字；颜色与 ICC 状态如实记录。
- [ ] A4 MediaBox 为 210 × 297 mm，不自动缩放；各稿与标记不重叠、不超出可印区。
- [ ] 同页粘贴的每一对正确，均正读；不是误做双面或折叠版。
- [ ] 双面 long/short 与驱动一致，背面位置正确，文字/Logo 未镜像，空位保留。
- [ ] 已打印校准页并量尺、透光；或明确写“仅数字几何检查，未验证设备对位”。
- [ ] 工艺蒙版尺寸、原点、命名、专色与叠印规则已按印厂要求检查；否则只列为待确认素材。

## 质检结论用语

每项记录为 `通过`、`失败`、`未验证` 或 `不适用`，可附证据路径。自动拼版报告只证明文件与几何检查，不证明照片身份、Logo 授权、颜色效果、印刷机精度或真实工艺。

# 拼版工具与安装后使用

`scripts/impose_cards.py` 用已经完成的**含出血图稿**生成 PDF，不生成球员照片或设计，也不会给成品图自动补真出血。

## 运行环境

Python 3.10+，依赖 Pillow 与 ReportLab。在任务环境的虚拟环境中安装缺少的依赖：

```sh
python -m pip install -r scripts/requirements.txt
```

无需 API 密钥、联网或 Adobe 账号即可拼版。设计阶段的图像工具由运行环境提供；本技能不绑定收费图像服务。

脚本不依赖 Codex、Claude 或 Gemini 的 SDK，可在任何具备上述运行环境并可访问素材的系统中运行。只有文本聊天时，这些命令是操作说明，不代表已经执行；依赖未安装时先报告实际缺项，不绕过宿主权限。

## 图稿输入约定

- 输入支持 PNG / JPEG，图像比例必须与含出血物理尺寸相符，默认比例为 69.5:94.9；容许约 0.25% 的像素取整误差。
- 使用已嵌入完整卡面、正常 EXIF 朝向的平面图稿。透明图像会被拒绝，避免把透明出血默默填白；请在设计阶段合成到最终不透明底。
- 图稿至少达到目标有效 PPI；四舍五入保留 0.5 ppi 余量。低清默认报错，`--allow-low-dpi` 才可生成明确标注为 proof 的低清样稿。
- CMYK JPEG 被拒绝。这个工具定位 RGB 桌面打样，不负责无 ICC 的隐式 CMYK 转换。输入若有 ICC 则需在图像编辑工具里先确认/转换为 sRGB。
- 每个卡 ID 仅可用字母、数字、下划线、短横线，不能重复。路径相对 job JSON 所在目录，不是相对当前终端。
- `common_back` 可提供同队通用背面；单卡 `back` 会覆盖它。跨球队应分别指定背面或分项目，不把一个队背面套到别队。
- 参数模板见 `assets/print-job.template.json`。图片路径是待替换的占位路径，不附带球员或球队数据。

## 常用命令

```sh
python scripts/impose_cards.py job.json --mode paste --out ./print/paste
python scripts/impose_cards.py job.json --mode duplex --flip long --out ./print/duplex-long
python scripts/impose_cards.py job.json --mode duplex --flip short --out ./print/duplex-short
python scripts/impose_cards.py job.json --mode singles --out ./print/singles
python scripts/impose_cards.py --mode calibration --flip long --out ./print/calibration-long
```

默认 A4 纵向 2×2，出血稿间距 8 mm，外部裁切线占 3 mm。paste 每页两对，duplex 每张纸四张卡。没有足够图稿填满一页时留白，不缩放。

`--back-dx-mm 0.3 --back-dy-mm -0.2` 仅修正 duplex/calibration 的背面；正值为背面 PDF 正读视角向右/向下。透光测量与修正符号见 印刷与对位（见本文件对应章节）。参数不能把图稿和标记推出保留 10 mm 的可印区。

工具拒绝覆盖已有目标文件。请使用新的输出目录或新版本目录，不用强制覆盖掩盖旧稿。所有输入、比例、有效 PPI 和几何先检查，错误时不写新的 PDF。

## 输出

- `a4-paste.pdf`：单面粘贴，页边只含配对 ID，卡面不加标签。
- `a4-duplex-long.pdf` / `a4-duplex-short.pdf`：正反交替的 PDF。
- `卡ID-front.pdf` / `卡ID-back.pdf`：带裁切线的单卡，具有 TrimBox / BleedBox。
- `calibration-long.pdf` / `calibration-short.pdf`：两页，不对称标记和 50 mm 标尺。
- `layout-report.json`：尺寸、输入分辨率/哈希、每页卡片位置、配对、翻边、偏移及局限；可用于复核，不是生产印前认证。

所有几何按 mm 转换为 PDF pt，页面渲染目标不由文件的 DPI 标签决定。工具只验证整体卡图像像素，不能自动知道卡图中某个局部人脸是否被放大；设计阶段仍需检查原图裁切有效像素。

## 能力边界

本工具不支持任意多拼、旋转横卡、折叠铰接拼版、圆角刀模、专色分色、PDF/X 输出或印刷机驱动控制。自定义尺寸可由 job 中 `trim_mm` / `bleed_mm` 设置，但如果 2×2 与标记放不下 A4，报错；应另做拼版，不能自动缩小成品。用户给印厂模板时优先按模板另行排版。

横版 `[88.9,63.5]` 可用 singles 输出单卡。默认 A4 纵向 2×2 不容纳两列横卡加裁切线与页边距，因此 paste/duplex 将拒绝，需另做横卡 A4 版式；这属于几何边界，与使用哪家 AI 无关。

# 跨工具安装与使用

技能名统一为 `stars-card-design`。跨工具兼容的是工作流和文件结构；实际看图、出图、导出和运行脚本取决于宿主能力。平台说明核对于 2026-10-19，尚未在每个平台登录导入实测。

## 选择哪种文件

| 使用环境 | 使用方式 |
|---|---|
| 支持 Agent Skills 的代理 | 安装完整 `stars-card-design/` 文件夹，入口是 `SKILL.md` |
| Claude 网页/桌面自定义技能入口 | 上传 `dist/stars-card-design-portable.zip`，其顶层仅有技能文件夹 |
| Claude Code | 把技能文件夹放入 `~/.claude/skills/` 或项目 `.claude/skills/` |
