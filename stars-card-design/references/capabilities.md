# 按运行能力适配

## 先识别能力，再承诺产物

使用宿主实际提供的能力，不从品牌名推断能力。网页聊天、终端代理、API 接入、可视化节点工作流中的同名模型，能力可能不同。无需每次打印一份能力清单给用户；只说明影响任务交付的限制。

| 实际能力 | 可完成的工作 | 不能冒称完成 |
|---|---|---|
| 只有文本 | 输入梳理、版式、尺寸、提示词、印刷说明、质检计划 | 已看照片、已生成卡图或下载文件 |
| 能看图，不能编辑 | 观察构图和可见元素，制作针对照片的设计说明与编辑提示词 | 人物已抠出、图像已合成 |
| 能文生图，不能参考图编辑 | 原创无人物背景/卡框、材质概念 | 新生成的人脸就是用户原照本人 |
| 能参考图编辑 | 指定原照片为编辑目标，保护人物/Logo，再对照原图检查 | 必定像素不变、必定身份一致 |
| 能原图嵌入/遮罩排版 | 保留实际源像素、叠加独立卡框和文字，是保真优先路线 | 没有执行合成却称已完成 |
| 能运行 Python 和写文件 | 在 Pillow、ReportLab 等依赖实际可用时运行拼版；无图像生成能力也可处理已提供的图稿 | 脚本执行就证明实机对位、CMYK 或人脸正确 |
| 有印前软件/印厂规范 | 按实际能力做页面框、ICC、专色或生产检查 | 未验证的 PDF/X、白墨、箔、实体镭射 |

## 能力不足时的可执行产物

- 缺图像编辑：提供准确引用用户上传图的编辑提示词，写清保留人物、只改哪些区域、卡型、方向和文字；若有精确排版能力，仍可用原照片嵌入版式。
- 不能看图：不要猜合照人数、球队、奖杯内容或照片构图。用用户文字资料做方案；把“请保留原图中所有成员”作为编辑约束，不说已确认人数。
- 缺文件运行环境：可交付提示词、布局坐标、人工导出和打印步骤，标明未生成 PDF。用户需要实际文件时，给出本包脚本的运行方法或让有相应能力的工具继续；不能编造附件。
- 只支持单条提示词的工具：给独立完整的视觉提示词；照片、精确文字和 Logo 在后续排版环节处理。若工具不支持保真编辑，只生成装饰素材。
- 缺图片或私有文件不可读：先完成不依赖它的部分；从当前聊天重新取得素材，不能依赖另一个平台的本地路径。

## 工具调用原则

查看图片使用宿主的图片查看能力；生成或编辑使用实际可用的图像工具；处理 PDF 使用文件/排版工具或已测试脚本。这些是能力名称，不要求某个具体函数。宿主有对应技能时遵守其规则；没有时不把它当作必装前提，也不自动切到收费 API。

不把某平台的 `image_gen`、`view_image`、`run_shell_command`、`$技能名` 或 `/技能名` 写成全局必需接口。原生技能宿主按自身方式加载；纯聊天以用户粘贴/上传的指令执行。技能不能给原本没有图像编辑或代码执行能力的模型增加这些能力。

## 素材在平台间的交接

交接包只携带必要的源照片、已确认事实、Logo、当前版式和导出规格；人像不默认放进可公开分发的技能包。路径是当前环境的引用，不是通用下载链接。附件 ID、图像引用、文件 URL、遮罩黑白语义都按目标工具定义确认。

保留用户已认可版本，注明当前产物为原图排版、AI 参考编辑、概念背景或生产稿。不得把参考编辑当成未重绘的源照片；有明显脸部变化时回退源照片排版或明确未通过保真检查。

## 宿主约束

仅在本次制卡任务中使用这些规则，不更改宿主的全局提示、账户、模型、权限或其他项目文件。平台需要用户确认工具调用时照其规则执行；不要声称本技能能绕过这些确认。当前用户的新选择覆盖本包的风格偏好与默认参数。
