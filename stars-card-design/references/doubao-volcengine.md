# 豆包与火山引擎运行适配

仅当本技能运行在豆包系 Agent、火山方舟、扣子、ArkClaw、iDA 或 OpenViking 环境时读取本文件。

## 能力映射

不要假设存在 Codex 或 OpenAI 专属工具。按当前环境实际暴露的能力完成以下映射：

| 球星卡步骤 | 豆包/火山引擎侧能力 |
|---|---|
| 读取用户照片 | 会话图片附件、文件节点或已授权的对象存储文件 |
| 生成人物与背景底图 | 支持参考图的 Seedream 图像生成/编辑能力，或宿主提供的等价图像工具 |
| 精确排版文字与 Logo | 工作流中的图像合成、画布、代码节点或其他确定性排版工具 |
| 导出正反面 | 文件输出节点、对象存储或会话附件 |

工具名称和模型版本可能随平台更新。优先选择当前可用、支持参考图输入和所需画幅的 Seedream 模型，不把某个模型 ID 写死为技能前提。

## 生成策略

1. 将用户照片作为人物身份参考图输入，不要只用文字重新描述人物。
2. 底图阶段明确要求：保留面部辨识度、肤色、体型、球衣和器材；预留姓名、号码与位置的安静区域；不要生成任何可见文字、数字、Logo、签名或二维码。
3. 如果工具支持多参考图，人物照片与用户提供的球队 Logo 分开处理。Logo 不进入生成式底图，应在排版阶段原样合成。
4. 将生成结果按比例裁切到技能规定的标准画布，不拉伸人物。
5. 使用确定性排版能力写入姓名、背号、位置、球队及背面内容，随后检查导出的实际像素。

如果当前 Agent 只有图像生成能力，没有确定性排版或文件导出能力，则只生成无字底图，并同时给出完整排版规格。必须明确说明尚未生成最终可交付卡片，不能把带乱码或错误文字的生成图冒充成成品。

## 豆包系平台上的交互

- 沿用主技能的分阶段提问，一次收齐照片、姓名、背号和位置。
- 图片附件无法读取时，先请用户重新上传或改用宿主支持的文件入口，不猜测图片内容。
- 用户已经在会话中给出的字段不再重复询问。
- 生成正反面时分别输出两个同尺寸文件；条件允许时再增加并排预览图。
- 不向用户索取火山引擎 API Key、Secret Key 或临时令牌。平台未配置图像工具时，直接说明需要管理员在 Agent 或工作流中接入。

## 平台边界

`SKILL.md`/ZIP 是火山引擎 Agent 产品的技能导入格式。不要声称普通豆包聊天客户端一定支持直接安装第三方技能；如果宿主没有“技能中心/导入技能”入口，应建议用户在支持技能导入的火山引擎 Agent 产品中安装，或把本技能作为工作流/系统提示词进行配置。
